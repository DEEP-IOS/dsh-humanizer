# dsh-humanizer

[![CI](https://github.com/deepios/dsh-humanizer/actions/workflows/ci.yml/badge.svg)](https://github.com/deepios/dsh-humanizer/actions)
[![npm](https://img.shields.io/npm/v/dsh-humanizer?label=npm)](https://www.npmjs.com/package/dsh-humanizer)

中文文本的深度编辑工作流，跑在 DeepSeek Harness 上。

## 它解决什么

生成文本的"AI 味"不在词表里，在决策结构里。同一个模型写不同主题，句子也许不同，但下面的东西会反复出现：同一套推理路径、同一套段落开合、同一种情绪载体、同一个结尾方式。这层结构上的同质，是检测器真正抓到的东西，也是读者觉得"哪里不对"的来源。

表层换词碰不到这一层。把"此外"换成"另外"，把"值得注意"删掉，机器腔只会换成另一种机器腔。要动的是决策：材料从哪来、焦点放哪里、这段承担什么任务、这个情绪用什么承载。

dsh-humanizer 提供的就是这套决策工作流。它把这件事拆成两半：

- 模型执行一套十步工作流，从叙事设计、语言分析到三轮改写、三重审核，每一步该读的方法论都写在引导里。
- 程序只守三条底线：分布画像、内容忠实守卫、工件质量门禁。程序不判断"像不像人"，只核对"该保留的有没有保留、该填的有没有填满"。

它不是一个 AI 检测器。不输出概率，不识别作者，不要求把文本提交给任何外部检测。

## 十步工作流

| 步 | 做什么 | 读 | 产出 |
|---|---|---|---|
| 0 | 接单卡：任务边界 + 内部基线 + 执行表字段 | §06.1/6.2、§11 | 接单卡 |
| 1 | 十维叙事设计（论证文本改走 §08） | §09、§08 | 工件 A |
| 2 | 功能路径图：八类路径逐形态 | §05 | 工件 B |
| 3 | 十五层语言分析：逐细分项 + 句式使用率 | §04 | 工件 C |
| 4 | 认识与来源图 | §06.4 | 工件 D |
| 5 | 问题清单：合并 A/B/C/D | §06.6 | 问题清单 |
| 6 | 改写轮一：只改材料/叙事/论证 | 工件 A—D | 修改记录 |
| 7 | 改写轮二：只改信息焦点/照应/句法 | 工件 A—D | 修改记录 |
| 8 | 改写轮三：只改词汇/搭配/虚词 | 工件 A—D | 修改记录 |
| 9 | 复核 | §15/§17/§13/§18 | 复核报告 |
| 10 | 交付 | — | 改写稿 + 全部工件 |

每一步只产出一个工件，过 `humanize_validate_artifact` 门禁才进下一步。一次做完等于偷工减料。

## 方法论

`references/` 随包分发 19 章，是这套工作流的全部理论依据。模型执行时按步读取，不靠程序硬编码：

| 章 | 主题 |
|---|---|
| 01 体系目标与边界 | 五个目标、六条不可承诺、主版本原则 |
| 02 人类作者感 | 材料来源、注意力选择、判断代价、声音稳定、重复有功能 |
| 03 复杂度模型 | 词汇/句法/篇章/认识/语用/语域七层 + 复杂度门控六问 |
| 04 十五层语言分析 | 语素构词到篇章话语，逐细分项 |
| 05 功能路径诊断 | 八类路径 + 重复判断七问 |
| 06 完整诊断流程 | 任务边界、内部基线、篇章任务图、认识来源图、修复尺度 |
| 07 改写决策与候选 | 决策十步 + 候选十来源 |
| 08 文章类方法 | 论证图、三段式、模板表达、专业文章保护 |
| 09 十维叙事审计 | 小说十维 + 三十项核心信号 + 模型指纹 |
| 10 三重审核与原理层自检 | 读者/编辑盲审、最小差异对照、留出测试 |
| 11 执行表 | 五张可填表 |
| 12 执行提示全文 | 可直接交给模型的完整提示 |
| 13 禁止与回退 | 十二类禁止手法 + 回退条件 |
| 14 检测原理 | 七类检测信号 + 资料边界 |
| 15 完成判据 | 十三条 |
| 16 问题对照库 | 十六类常见问题的证据、误判与处理 |
| 17 复核清单 | 字词/句法/信息/段落/全文五级 |
| 18 实战迭代经验 | 章节任务四类轮换、七类高危模式、脚本核验清单 |

## 安装

```sh
dsh plugin --profile web add dsh-humanizer
```

装完重启 web，bundle 层栈在 boot 时合成。

## 使用

对模型说「用 humanizer 处理这段文本」。工作流常驻 system prompt，模型按十步执行，用 `humanize_reference` 读取方法论章节。

| 工具 | 作用 |
|---|---|
| `humanize_profile(text)` | 分布画像：句长、短长句占比、连词密度、内容锚点 |
| `humanize_guard(original, rewritten)` | 内容忠实守卫：锚点保真 + 禁止条件扫描 |
| `humanize_validate_artifact(artifact, source)` | 工件门禁：拒占位空话、空数组、假证据、短判断 |
| `humanize_reference(name)` | 读取 references/ 章节全文 |

CLI：

```sh
node scripts/guard-humanizer.mjs profile ./文本.md
node scripts/guard-humanizer.mjs guard ./原文.md ./改写稿.md
```
